# よりみち大江ナビ

福知山市大江町内宮地区の観光を支援する、スマートフォン対応のWebアプリ試作です。コース選択、列車時刻、GPSによる到着判定、手動案内、感情付きひとりごと、共通解説、通知音、SQLiteイベント記録を実装しています。

## 起動

必要環境はNode.js 20以降とnpmです。初回に依存関係をインストールします。

```powershell
npm install
npm run dev
```

PCでは `http://localhost:5173` を開きます。Express APIはポート3001で起動し、Viteが `/api` を転送します。本番ビルドは `npm run build`、生成物は `dist/` です。本番起動は `npm start`（ポート3001）です。

## スマートフォンとGPS

このアプリはホーム画面に追加できるPWAです。スマートフォンからHTTPSの公開URLを開き、iPhoneはSafariの共有メニューから「ホーム画面に追加」、AndroidはChromeのメニューから「アプリをインストール」または「ホーム画面に追加」を選んでください。レイアウトはスマートフォン幅に対応し、インストール後はアプリ風の全画面で起動します。

モバイルブラウザの位置情報APIとPWAインストールにはHTTPS（または端末上のlocalhost）が必要です。実機の確認では、PCからアクセスできるHTTPSの開発URL（例：Cloudflare Tunnel、開発用HTTPSホスティング）を使い、画面とAPIの両方を同じHTTPSオリジン経由で公開してください。トンネルサービスの認証や設定はサービス側の手順に従います。LAN内の `http://<PCのIP>:5173` はGPSを許可しない端末があります。

Service Workerは画面とアイコンをキャッシュします。案内データ送信やイベント記録にはサーバー接続が必要で、オフラインでのGPS案内は保証しません。公開運用にはHTTPS対応のNode.jsホスティングと永続ディスクが必要です（SQLiteの記録を保持するため）。静的サイトだけのホスティングではAPIと記録機能は動作しません。

「案内をはじめる」を押すとブラウザが位置情報許可を求めます。高精度位置を使い、精度100m以内、スポット半径30m以内が10秒続く場合に到着と判定します。拒否・非対応・測位精度不足の場合は設定メニューから地点を選択できます。現在地の連続座標は保存しません。アプリを再読み込みすると、進行中セッションはlocalStorageから復元します。

## 画面操作

- 開始画面で帰りの列車、コース、通知音を選びます。列車時刻は方面を選ぶセレクトボックスから指定します。福知山方面と天橋立・宮津方面を用意し、添付された2026年3月14日改正の時刻表画像から転記しています。
- ひとりごとの「詳しく知る」でスポット共通解説を開きます。戻るとチャット履歴が残ります。
- 右上メニューから地点を手動変更したり、途中で案内を終了したりできます。
- 到着案内は登録順を強制せず、コース内の未訪問スポットを検知します。同一話題は1回のみです。
- 本殿と龍灯の杉は共通エリアです。本殿の案内から3分後に、案内間隔などの条件を満たし、アプリが表示中であれば龍灯の杉を案内します。手動地点変更でも補完できます。
- 選択した列車の発車25分前から帰着案内に切り替えます。駅での帰着表示は全6地点を訪れ、出発駅から100m以上離れたことを確認した後に行います。帰着時に自動終了はせず、「終了」を押します。

## 通知音

`public/sounds/notification.wav` は本アプリ用に合成した、短い2音のチャイムです。ブラウザ制限や端末設定で再生できなくても、案内表示は続行します。Web Audio APIで鳴らすため、別途外部音声配信は必要ありません。

## 保存データと研究ログ

- セッション状態：ブラウザのlocalStorage（キー `ooe-session-v1`）
- サーバーログ：`data/ooe-navi.sqlite`（SQLite、WALモード）
- 位置履歴は保管しません。到着／手動変更、発言、感情抽選候補、通知結果、詳細閲覧、帰着案内、終了をイベント単位で記録します。
- CSV出力は一般画面に表示しません。PowerShellで ` $env:ADMIN_TOKEN='十分に長い秘密値'; npm start ` として起動した上で、管理者だけが `http://localhost:3001/api/admin/events.csv?token=<秘密値>` にアクセスします。トークンはURL履歴等に残るため、公開環境ではリバースプロキシの認証とHTTPSを併用してください。未設定時はCSV出力を無効にします。

## 設定とデータ

スポット座標、セリフ、解説文、列車時刻、抽選確率、GPS判定半径・継続時間、最小通知間隔などは `src/data.ts` に集約しています。初期感情確率は好奇心・疑問・関心・通常を各25%とし、同じ感情の連続を避けて残りの重みを再正規化します。拗ねるは3分の無操作後に低確率で1地点1回のみ判定します。

画像は `public/images/` に配置しています。キャラクター画像と6地点の写真、時刻表写真は提供素材です。

## 実装上の確認事項・限界

- GitHubの指定リポジトリは空でした。そのためこのフォルダで新規にアプリを構成しました。
- 仕様書に記載の6スポットのセリフ・詳細文を登録しています。仕様書自体が現地資料での最終確認を求めているため、固有の伝承・史実・建築説明は実験公開前に監修してください。
- GPS座標と、特に本殿・駅・天岩戸神社の代表点は現地で測位確認が必要です。本殿と龍灯の杉は個別GPS判定をしません。
- 試作コースは1つです。到着地点ごとの話題は仕様書にある1話題のみで、同一地点の3分・7分後に追加話題を新規生成しません。共有エリアの龍灯の杉への切替は別地点案内です。
- 拗ねるは試作ルールに沿い無操作後に抽選しますが、「操作なし」を利用者の無視と判断せず、ログ上も反応有無を拗ねるイベントとは別に扱います。
- バックグラウンドでのGPS・通知音は保証しません。タブ復帰後に列車時刻を再評価します。
- 現地調整対象は位置半径・精度制限・滞在継続時間・本殿からの切替時間・列車時刻・解説文監修です。

## 技術

React 18、TypeScript、Vite、Express、better-sqlite3、lucide-react。通知音はWeb Audio APIで合成します。位置取得にはブラウザGeolocation APIを使用します。

## 画面操作の補足

- 列車選択は「方面」と「列車時刻」のセレクトボックスです。福知山方面・天橋立／宮津方面の時刻を選べます。時刻は添付の2026年3月14日改正時刻表に基づきます。
- ひとりごとは最新の発言を一番上に置き、過去の発言は下へスクロールして確認できます。感情ラベルは画面に表示しません。
- 「次のスポットへ」を押すと、未案内の次のスポットへ現在地を切り替えて、発言を表示します。
- 画面全体は以前より約0.8倍の表示サイズにしています。
- 開発用シミュレーションの「拗ねる」で、現在地点の拗ねる発言を手動表示できます（同一地点では1回まで）。
