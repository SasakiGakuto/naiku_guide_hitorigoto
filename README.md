# 大江案内鬼くろおにくん

「大江案内鬼くろおにくん」は、福知山市大江町内宮地区の観光を支援するスマートフォン対応のWebアプリ試作です。コース選択、列車時刻、GPSによる到着判定、手動案内、感情付きひとりごと、共通解説、通知音、SQLiteイベント記録を実装しています。

## 起動

必要環境はNode.js 20以降とnpmです。初回に依存関係をインストールします。

```powershell
npm install
npm run dev
```

PCでは `http://localhost:5173` を開きます。Express APIはポート3001で起動し、Viteが `/api` を転送します。本番ビルドは `npm run build`、生成物は `dist/` です。本番起動は `npm start`（ポート3001）です。

## スマートフォンとGPS

このアプリはホーム画面に追加できるPWAです。スマートフォンからHTTPSの公開URLを開き、iPhoneはSafariの共有メニューから「ホーム画面に追加」、AndroidはChromeのメニューから「アプリをインストール」または「ホーム画面に追加」を選んでください。レイアウトはスマートフォン幅に対応し、インストール後はアプリ風の全画面で起動します。

モバイルブラウザの位置情報APIとPWAインストールにはHTTPS（または端末上のlocalhost）が必要です。実機の確認では、PCからアクセスできるHTTPSの開発URL（例：Cloudflare Tunnel、開発用HTTPSホスティング）を使い、画面とAPIの両方を同じHTTPSオリジン経由で公開してください。トンネルサービスの認証や設定はサービス側の手順に従います。LAN内の `http://<PCのIP>:5173` はGPSを許可しない端末があります。

Service Workerは画面とアイコンをキャッシュします。案内データ送信やイベント記録にはサーバー接続が必要で、オフラインでのGPS案内は保証しません。公開運用にはHTTPS対応のNode.jsホスティングと永続ディスクが必要です（SQLiteの記録を保持するため）。静的サイトだけのホスティングではAPIと記録機能は動作しません。

「案内をはじめる」を押すとブラウザが位置情報許可を求めます。高精度位置を要求し、精度100m以内かつ15秒以内の測位を直近5件中3件以上確認してから到着判定します。麻呂子スギは50m、日室ヶ岳遥拝所と天岩戸神社は30m、麻呂子スギ・黒木の鳥居・本殿・龍灯の杉はそれぞれの既存判定円の和集合を共通エリアとして判定します。共通エリア到着時は探索開始のひとりごとを一度だけ表示し、対象4地点の個別案内は利用者が各カードの「発見！」を押したときに表示します。測位権限拒否・タイムアウト・取得失敗を区別し、開発モードの案内設定にGPS診断情報を表示します。拒否・非対応・測位精度不足の場合は設定メニューから地点を選択できます。現在地の連続座標はSQLiteに保存しません。アプリを再読み込みすると、進行中セッションはlocalStorageから復元します。

## 画面操作

- 開始画面で帰りの列車、コース、通知音を選びます。列車時刻は方面を選ぶセレクトボックスから指定します。福知山方面と天橋立・宮津方面を用意し、添付された2026年3月14日改正の時刻表画像から転記しています。
- ひとりごとの「詳しく知る」でスポット共通解説を開きます。戻るとチャット履歴が残ります。
- 右上メニューから地点を手動変更したり、途中で案内を終了したりできます。
- 到着案内は登録順を強制せず、コース内の未訪問スポットを検知します。同一話題は1回のみです。
- M01〜M04は共通GPSエリアの探索対象です。共通エリアへの到着時に開始のひとりごとを一度表示し、4枚の写真カードから好きな順に発見できます。発見済み状態と開始セリフはセッションのlocalStorageに保存します。M05・M06は個別GPS案内を維持します。
- 選択した列車の発車25分前から帰着案内に切り替えます。駅での帰着表示は全6地点を訪れ、出発駅から100m以上離れたことを確認した後に行います。帰着時に自動終了はせず、「終了」を押します。

## 日常的なひとりごと

案内開始3分後に初回を1回表示し、2回目以降はGPSで同じ場所に5分以上滞在し、直前のスポット・探索開始／日常発言から15分以上経過した場合に表示します。1セッション最大3回で、既出文は再利用しません。詳細閲覧中、バックグラウンド中、帰着案内中は表示を保留または停止します。探索開始やスポット発見の発言は、日常的なひとりごとより優先されます。通知音と「詳しく知る」ボタンはありません。初期文章は `src/daily-utterances.json` にあり、起動時にSQLiteの `daily_utterances` マスタへ不足分を追加します。配信は `/api/daily-utterances` から行います。研究ログは既存 `event_logs` の payload と utterance_id を使って記録します。


## 発見型観光

共通エリア（M01〜M04）へGPSで安定入域すると、チャット欄に探索カードを表示し、探索開始セリフをA/Bから等確率で1つ選んで既存のひとりごと欄に追加します。写真カードと発見ボタンはチャット欄に2列で表示します。結果と発見履歴はセッションのlocalStorageへ保存し、再入域・再読み込みでは開始セリフを再表示しません。発見順は自由で、各ボタンは各セッションで一度だけ有効です。発見時には既存の感情抽選によるスポット発言をチャット履歴に表示し、「詳しく知る」から詳細画面を開けます。対象画像は `public/images/spots/` に4地点分登録済みで、読み込み失敗時は代替表示になります。


## 開発用の発言テスト

「地点を選ぶ」画面内の開発パネルに、拗ねる・日常・帰着警告の3種類のテストボタンがあります。Viteの開発モード（`npm run dev`）でだけ表示され、本番ビルドには含まれません。テスト発言は `debug_manual` イベントとして記録し、訪問済み地点、感情抽選履歴、日常発言の回数、帰着案内状態を変更しません。拗ねるテストの発言カードから、既存の詳細画面も確認できます。

## コース詳細

開始画面のコースカード右側の「詳細」から、出発駅、コースデータのスポット順、帰着駅を確認できます。訪問スポット一覧は `src/data.ts` の各コースの `spotIds` と現在のスポット名から生成されます。詳細を開閉しても選択コースは変わりません。
## 通知音

`public/sounds/notification.wav` は本アプリ用に合成した、短い2音のチャイムです。ブラウザ制限や端末設定で再生できなくても、案内表示は続行します。Web Audio APIで鳴らすため、別途外部音声配信は必要ありません。

## 保存データと研究ログ

- 匿名利用者ID：`ooe-visitor-v1` にUUIDを保存し、同じブラウザで別日に利用しても維持します。氏名・メール・ログイン情報は収集しません。
- 観光セッション：`ooe-session-v1` にバージョン付きで保存します。`visitor_id`、`session_id`、観光日（Asia/Tokyo）、開始日時、選択コース、列車発車予定日時、セッション状態、最終保存日時と案内進行状況・チャット履歴を含みます。
- 同じ日本時間の日付で、セッションがactiveかつ列車発車前ならメイン画面へ復元します。列車発車25分前からは帰着案内に入り、発車後・翌日・終了後は復元しません。日付変更時は開いたままの画面でもセッションを終了します。
- セッションを終了して再び案内を開始すると、新しい `session_id` を発行します。visitor IDと過去の研究ログは維持します。
- サーバーDBの `sessions` と `event_logs` に `visitor_id` を追加し、既存SQLiteへ列追加で移行します。既存ログは削除しません。
- 同じブラウザの別タブにはlocalStorage更新を通知し、同じvisitor/session状態へ同期します。発見操作はWeb Locks APIがある場合に排他し、SQLiteにも重複防止を追加します。
- 開発モードの案内設定には「セッション終了」があります。確認後に理由 `debug_session_end` で現在のセッションだけを終了し、開始画面へ戻ります。visitor IDと過去ログは維持されます。
- サーバーログ：`data/ooe-navi.sqlite`（SQLite、WALモード）
- 位置履歴は保管しません。到着／手動変更、発言、感情抽選候補、通知結果、詳細閲覧、帰着案内、終了をイベント単位で記録します。
- CSV出力は一般画面に表示しません。PowerShellで ` $env:ADMIN_TOKEN='十分に長い秘密値'; npm start ` として起動した上で、管理者だけが `http://localhost:3001/api/admin/events.csv?token=<秘密値>` にアクセスします。トークンはURL履歴等に残るため、公開環境ではリバースプロキシの認証とHTTPSを併用してください。未設定時はCSV出力を無効にします。

## 設定とデータ

スポット座標、セリフ、解説文、列車時刻、抽選確率、GPS判定半径・安定化条件、日常発言の間隔と上限などは `src/data.ts` に集約しています。初期感情確率は好奇心・疑問・関心・通常を各25%とし、同じ感情の連続を避けて残りの重みを再正規化します。スポット発言の1分後までにそのスポットの詳細を開いていない場合、拗ねる発言を50%の確率で1回だけ表示します。日常ひとりごとの初回は案内開始3分後、以降は同一場所5分滞在かつ前回のスポット・探索開始／日常発言から15分後です。

画像は `public/images/` に配置しています。キャラクター画像と6地点の写真、時刻表写真は提供素材です。ホーム画面アイコンは `public/icon-192.png`、`public/icon-512.png`、`public/icon-maskable-512.png`、Apple Touch Iconは `public/apple-touch-icon.png` です。いずれも提供されたくろおにくん画像を切り出して作成し、Service Workerのシェルキャッシュを更新しています。

## 実装上の確認事項・限界

- 仕様書に記載の6スポットのセリフ・詳細文を登録しています。仕様書自体が現地資料での最終確認を求めているため、固有の伝承・史実・建築説明は実験公開前に監修してください。
- GPS座標と、特に本殿・駅・天岩戸神社の代表点は現地で測位確認が必要です。共通GPSエリアは麻呂子スギ・黒木の鳥居・本殿・龍灯の杉の個別判定円の和集合です。
- 現在登録されているコースは1つです。M01〜M04は発見ボタンで、M05・M06は個別GPS判定で案内します。共通エリアのスポット発言に時間差の自動案内はありません。
- 拗ねるはスポット発言から1分後、詳細が開かれていない場合に50%で抽選します。抽選結果と詳細閲覧の有無を記録します。
- バックグラウンドでのGPS・通知音は保証しません。タブ復帰後に列車時刻を再評価します。
- 現地調整対象は位置半径・精度制限・滞在継続時間・本殿からの切替時間・列車時刻・解説文監修です。

## テスト

`npm test` を実行すると、共通エリアの安定判定、探索セリフの50/50選択、発見重複防止、コース表示順、JST日付・発車時刻に基づくセッション復元条件を確認できます。

## 技術

React 18、TypeScript、Vite、Express、better-sqlite3、lucide-react。通知音はWeb Audio APIで合成します。位置取得にはブラウザGeolocation APIを使用します。

## 画面操作の補足

- 列車選択は「方面」と「列車時刻」のセレクトボックスです。福知山方面・天橋立／宮津方面の時刻を選べます。時刻は添付の2026年3月14日改正時刻表に基づきます。
- ひとりごとは最新の発言を一番上に置き、過去の発言は下へスクロールして確認できます。感情ラベルは画面に表示しません。
- 案内開始時に「ぼくはくろおにくん！　大江のことは僕にまかせて！」をひとりごととして表示します。
- 画面全体は以前より約0.8倍の表示サイズにしています。
- 開発用パネルでは拗ねる・日常・帰着警告の表示をテストできます。テスト発言は通常の訪問履歴や発言回数に加算しません。

## メイン画面と詳細画面

- メイン画面では、現在地・次の列車を上部に置き、ひとりごと履歴を独立してスクロールできます。最新の発言を上部に表示し、過去の発言を読んでいる間は履歴の位置を保ちます。
- 元伊勢内宮の探索中は、写真付きの2列スポットパネルを画面下部に固定します。探索エリア外、全地点発見後、帰着案内中はパネルを隠します。
- 案内終了と通知音・開発設定は右上メニューから開きます。案内開始後の画面には地点変更・次のスポットへのボタンを表示しません。
- 詳細画面は対象スポットの写真を先頭に表示し、現在地・列車カードや探索パネルを隠します。詳細から戻るとひとりごとのスクロール位置を復元します。

## Gemini APIによる質問機能

案内中はメイン画面のチャット履歴の下から、くろおにくんへ自由に質問できます。利用者の質問は青色の吹き出し、回答は通常のくろおにくんの発言カードに分けて表示します。回答待ち中も履歴をスクロールでき、GPS、スポット発見、帰着案内は従来どおり動作します。回答中の二重送信を防ぎ、セッションを終了した後に届いた回答は画面へ追加しません。同日中にセッションを再開すると、質問・回答はほかの履歴と同じくlocalStorageから戻ります。翌日や新しいセッションには引き継ぎません。

質問と回答は研究用としてSQLite互換DBの `ai_questions` に全文保存します。回答できなかった質問も `response_status` と応答時間を記録します。visitor_id、session_id、question_id、質問・回答日時、モデル、入出力トークン数、応答状態、応答時間を保存します。同じquestion_idの再送は重複記録・再生成を避けます。Geminiへ渡す会話は直近20発言までで、自発的なひとりごとと利用者の質問・AI回答を時系列で含めます。GPS発言、テスト発言、エラー表示などは送信しません。質問は2,000文字まで、同一visitor_idは1分8件、同一接続元は1分30件までの短時間レート制限があります。日単位のアプリ内質問上限はありません。

質問内容は研究目的で全文を記録します。自由入力には個人情報が含まれる可能性があるため、公開前に研究参加者への説明・同意手続きと研究データの取扱いを確認してください。

### GeminiモデルとAPIキー

既定モデルは `gemini-3.5-flash-lite` です。モデルIDは `GEMINI_MODEL` で変更できます。Googleの現在のモデル・料金案内では、Gemini 3.5 Flash-Liteは安定版の軽量モデルで無料枠が掲載されています。無料枠の上限はGoogle側で変わる場合があり、APIキーが有料枠のプロジェクトに属する場合は利用料が発生する可能性があります。アプリは別モデルへの自動切替や課金設定の有効化を行いません。Google Search Groundingも使用しません。

ローカルでは `.env.example` を参考に、Git管理外の `.env` に `GEMINI_API_KEY` と任意の `GEMINI_MODEL` を設定します。起動時に読み込むため、`.env` をGitHubへ追加しないでください。現在の開発環境ではnpmレジストリのDNS/TLS接続に失敗し、`@google/genai` SDKを取得できなかったため、Gemini公式の `generateContent` HTTPS APIをサーバーから直接呼び出しています。APIキーはリクエストヘッダーにだけ渡し、ブラウザ・ログには出しません。

### SQLite・Vercel設定

ローカルのExpressサーバーは既存DBに `ai_questions` と短時間制限用テーブルを追加します。管理者は `ADMIN_TOKEN` を設定し、次のようにBearer認証付きで質問履歴をCSV出力できます。

```powershell
Invoke-WebRequest -Headers @{ Authorization = "Bearer $env:ADMIN_TOKEN" } `
  http://localhost:3001/api/admin/ai-questions.csv -OutFile ai-questions.csv
```

Vercel Functionsのファイルシステムは永続DBとして使えないため、VercelではSQLite互換の永続DBとしてTurso/libSQLを利用します。プロジェクト環境変数に `GEMINI_API_KEY`、`GEMINI_MODEL`、`TURSO_DATABASE_URL`、`TURSO_AUTH_TOKEN`、`ADMIN_TOKEN` を登録してください。TursoのURLは `libsql://...` またはHTTPS URLです。AIログ用テーブルは初回の質問時に自動作成します。Tursoを設定しない間、Vercelの質問APIは安全側に停止し、ローカルのSQLiteへは書き込みません。

公開前に、Google AI Studioのプロジェクトが無料枠で動作すること、TursoのDB/tokenが作成済みであることを確認してからVercelに環境変数を設定し、再デプロイしてください。Vercelの管理者CSVは `GET /api/admin/ai-questions.csv` に `Authorization: Bearer <ADMIN_TOKEN>` を付けて取得します。Gemini質問機能のデプロイと実API呼び出しは、この作業では行っていません。
